## 1. Assessment and recommended order

The two audits are complementary. **Sol 6.1 Ultra provides the stronger immediate playback/recording defect set; Astra 6 Ultra provides the broader persistence, cancellation, geographic-lighting and musical-composition investigation.** Neither report is a substitute for source verification. All 49 original finding IDs are retained below, consolidated into 40 work items, including intentionally deferred opportunities and one unresolved concurrency lead.

The first repairs should protect library metadata and completed exports, restore affected selected-tour startup, prevent optional cache work from withholding usable analysis, and make recording failure truthful. The next layer is cancellation and bounded preparation: a failed audio job must stop its siblings, and cloud/stem work must leave the main thread available. Lighting coherence and measured render optimization follow those correctness repairs.

Independent investigation materially changes the evidence:

1. **Astra R-02 is promoted from a fake-ordering lead to a native IndexedDB reproduction.** An old prune can delete a row written by a newer scan. The read and delete transactions have different ownership moments.
2. **Astra R-04 remains an unconfirmed lead.** Six native startup/adoption scenarios repeated in five fresh browser contexts (30 runs total) did not reproduce stale restoration; its artificial callback-delay example is insufficient to call this a demonstrated native-browser defect.
3. **Audio failure cleanup is worse than merely finishing already-started work.** A surviving band-pool loop can allocate five additional OfflineAudioContexts after the aggregate analysis promise has rejected. This extends Astra PERF-08; it is not counted as an unrelated duplicate.
4. **Manual comparison workflows have a concrete baseline problem.** Some “base” checkouts resolve to the candidate SHA; other base-capture steps require a PR event that the workflow cannot receive. A green manual comparison may therefore establish repeatability, not preservation against an earlier revision.
5. **Several graphics claims need narrower wording.** Reflected-tree gust disagreement is supported; a reflected water-surface disagreement is not, because that water plane is clipped from the mirror. Mirror-sky work repeats at half the native-scale partition backing including overscan, not at full output resolution.

No P0 outage, exploitable vulnerability, physical-device memory exhaustion, universal GPU bottleneck, or guaranteed visual improvement is established. A green technical capture remains separate from musical/artistic acceptance.

### Verification method and coverage

A separate snapshot was reconstructed from committed Git objects and matching local source copies; **all 1,518 blobs were independently checked against the authenticated GitHub tree, with zero mismatches**. Existing working trees and original audit artifacts were left untouched. Tests/probes operate on this snapshot; scratch scripts and captured evidence remain outside committed application source.

Review covered every original finding's implementation path, source references, available supporting artifacts and corresponding recommendation. Focused independent probes exercise real production functions with explicitly identified file, worker, encoder, DOM or native-audio boundaries. The IndexedDB follow-up uses actual Chromium IndexedDB. Render branch counts, scalar color calculations and shader inspection do not by themselves establish GPU savings or aesthetic severity.

Coverage is partial for optional server adapters, adversarial/security analysis, all cache/browser upgrade cases, exact codec limits and every song/world combination. This consolidation did not rerun the original RTX performance sessions, conduct physical-device testing, inspect a physical display, or grant artistic acceptance. External Pages configuration, deployment bytes and branch protection were not verified.

| Code | Meaning |

| **C** | Confirmed by executable source/control-flow inspection |
| **A** | Original measured artifact inspected; no new equivalent hardware measurement claimed |
| **O** | Confirmed design/content limitation or improvement opportunity; not a malfunction |
| **H** | Performance, memory or perceptual impact remains a hypothesis requiring measurement |

## 4. Verified mechanisms, disagreements and repairs

### 4.1 Tour availability and musical staging — C01, C28

Sol's highest-value unique finding is real: the selected/persisted Tetons tour can fail before playback with `Tour timeline has no feasible aim state`. The independently rerun minimized schedule reproduces the throw. Current-step motion is limited to 12°/s in outro/breakdown while the future-station feasibility filter still assumes the general 25°/s rate. That can preserve a beam state which later cannot reach the required aim. The code has a demotion recovery for an active lock, but the failing no-state branch has no active lock to demote. See [src/world/terrain/TourTimeline.js:119-148](https://github.com/aepler315/midio-pixel/blob/8f7c10fecdb9c436f7e789ec094c79efe88eff31/src/world/terrain/TourTimeline.js#L119-L148) and [src/world/terrain/TourRuntime.js:5-18](https://github.com/aepler315/midio-pixel/blob/8f7c10fecdb9c436f7e789ec094c79efe88eff31/src/world/terrain/TourRuntime.js#L5-L18).

Repair the feasibility model using the actual future role-dependent rate budget, and add bounded legal recovery when no state survives. Do not “fix” this by lifting comfort/yaw limits, removing station constraints indiscriminately, or returning an arbitrary invalid camera. Diagnostic transformations which make the replay succeed identify a cause; they are not production-ready algorithms. Acceptance needs the minimized schedule, real-upload selected/persisted tour, normal default Landscape and a broader song-role corpus, with rate/altitude/clearance/continuity retained.

Astra G9 is a separate issue even once startup works. Its fixed-clock report stores a complete 89,984 ms plan with scenic quality ratio 0.8651 but **four of nine heroes with zero projected framing**. Misses occur near 23.179, 31.731, 83.012 and 87.885 seconds, including the final chorus/outro. The captured frames cover only 12–14 seconds; the later misses are planned projection diagnostics, not viewed footage. The source computes scenic quality independently from hero framing, and the dedicated smoke filters framing assertions to station visits: [src/world/terrain/TourTimeline.js:188-240](https://github.com/aepler315/midio-pixel/blob/8f7c10fecdb9c436f7e789ec094c79efe88eff31/src/world/terrain/TourTimeline.js#L188-L240), [tools/teton-tour-smoke.mjs:24-28](https://github.com/aepler315/midio-pixel/blob/8f7c10fecdb9c436f7e789ec094c79efe88eff31/tools/teton-tour-smoke.mjs#L24-L28).

The distant-alternative pass accepts a candidate after yaw/scenic checks without requiring the newly targeted candidate to pass a projection-coverage threshold: [src/world/terrain/TourTimeline.js:243-303](https://github.com/aepler315/midio-pixel/blob/8f7c10fecdb9c436f7e789ec094c79efe88eff31/src/world/terrain/TourTimeline.js#L243-L303). This is a useful repair target, not proof that every accepted alternative fails. Add separate semantic coverage reporting and preserve safe short-song fallbacks. Start with “no regression against accepted fixture coverage” and explicit review of endings; do not invent a universal percentage. Actual visibility also needs terrain occlusion, subject pixel footprint, cinematic/user camera transforms and continuous music-backed clips.

### 4.2 Library preservation and identity — C02–C05

**C02: confirmed metadata loss.** A still-listed file whose `getFile()` throws is omitted from scan results. Prune treats omission as deletion, so play count, duration and earned tags disappear; a healthy next scan recreates a fresh row. Source audio is not deleted. A synchronous directory-enumeration failure also yields incomplete information; asynchronous iterator rejection already propagates and should not be misreported as the same swallowed case. See [src/library/LibraryScanner.js:56-64](https://github.com/aepler315/midio-pixel/blob/8f7c10fecdb9c436f7e789ec094c79efe88eff31/src/library/LibraryScanner.js#L56-L64), [src/library/LibraryScanner.js:165-183](https://github.com/aepler315/midio-pixel/blob/8f7c10fecdb9c436f7e789ec094c79efe88eff31/src/library/LibraryScanner.js#L165-L183), [src/library/MusicLibrary.js:230-265](https://github.com/aepler315/midio-pixel/blob/8f7c10fecdb9c436f7e789ec094c79efe88eff31/src/library/MusicLibrary.js#L230-L265).

Return observed paths, successful rows, failed prefixes and completeness separately. Prune only after a complete authorized walk, or only inside subtrees proven complete. Preserve old metadata where access failed, while retaining intentional deletion behavior after a healthy scan. Acceptance must inspect durable rows after browser reload, not only the visible list.

**C03: Astra's tentative race is now native-reproduced.** `pruneTracks` reads candidate rows in a readonly transaction, then creates a separate readwrite delete transaction without a current-scan authorization check. The service checks generation before/after the await, which cannot revoke an already-running mutation. A valid IndexedDB transaction queue can order the old read, new scan's write, and old delete so the old delete runs last. ### Minimal recipes for the most consequential follow-ups

**Native stale prune (C03):**

1. In a fresh same-origin browser IndexedDB, seed a library root and a track with playCount 1.
2. Hold a legitimate readwrite transaction on the tracks store using chained native requests.
3. Start an old completed scan whose keep set omits the track, allowing its readonly prune request to queue.
4. Cancel the old scan, then start a replacement scan which still contains the track, allowing its write transaction to queue after that read.
5. Release the blocker. The old read completes; the replacement write runs; the old prune's separately created delete follows it.
6. Wait for both service operations, then read durable rows with a fresh transaction. The reproduced result is empty; a later healthy rescan restores the file with playCount 0. Do not intercept/delay IDB success callbacks.
7. A repair must retain the replacement row and history while still permitting a current complete scan to delete genuinely absent paths.

**Post-rejection band allocation (C12):**

1. Execute real `separateStemsPooled` with concurrency two and a seven-band input.
2. Substitute only the native OfflineAudioContext boundary with individually controlled rendering promises.
3. Reject one rendering promise, observe the returned aggregate reject, then resolve the sibling.
4. Observe whether new context construction continues. Current code constructs five additional contexts and invokes successful callbacks after failure.
5. A repair must prevent new allocations/publication, preserve the original error and release surviving ownership. Native in-flight rendering itself may not be interruptible.

**Planner/recorder/export checks:** preserve Sol's minimized role schedule and Astra's three naming collision pairs; run the actual production helpers on the pinned source. Retain real-codec validation as a separate gate rather than treating placeholder finalization bytes as a real damaged-media example.
