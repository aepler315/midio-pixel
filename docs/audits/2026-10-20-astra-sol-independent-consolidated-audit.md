# Midio Pixel: independent Astra / Sol audit, verification and implementation roadmap

**Date:** October 20, 2026 (America/Los_Angeles). **Repository:** `aepler315/midio-pixel`. **Verified current-main snapshot:** [`cace36893003e4161b243f22a69204be17181df6`](https://github.com/aepler315/midio-pixel/commit/cace36893003e4161b243f22a69204be17181df6). **Scope:** investigation and documentation only; no application changes.

## 1. Assessment

The strongest combined repair queue is: protect library metadata and completed export files; repair input-dependent tour readiness; make recording results truthful; let completed analysis proceed when optional cache work stalls; and cancel sibling work when analysis fails. Rendering improvements should follow measured costs and preserve the current presentation, resource-admission and capture contracts.

**Sol 6.1 Ultra contributes the stronger immediate playback/recording failure investigation. Astra 6 Ultra contributes the broader durable-state, export, cancellation, geographic-lighting and musical-composition investigation.** Both are useful; neither should be adopted unchanged. Their 49 original finding IDs are preserved below, including unresolved claims and design opportunities. The register retains C01–C40 from the earlier repository consolidation for continuity, updates their evidence against current main, and adds C41–C43 for discoveries from this review.

Fresh investigation strengthens or changes several conclusions:

- The selected-tour planner failure reproduces with the retained worker input and with a smaller 90-second schedule. The 60- and 120-second controls pass. This is input-dependent; it does not establish that every tour or clean default Landscape fails.
- The old-scan prune race reproduces in native Chromium IndexedDB, five of five runs. A replacement scan's metadata can be deleted by the old scan after its ownership has ended.
- A separate **two-tab root-allocation race** reproduces three of three times: concurrent fallback folders with the same display name receive one root ID, and the two real scans can leave the durable track list empty. Sequential same-name and concurrent different-name controls pass.
- A failed band-analysis pool can construct five additional native-context substitutes and publish six completion callbacks after its aggregate promise has rejected. This extends Astra's sibling-work finding.
- One archived Astra capture is marked passed despite two WebGL invalid-value warnings. The warning-acceptance gap is confirmed; the underlying renderer/lifecycle cause and visual impact remain unresolved.
- The alleged startup-restore race remains unconfirmed in fresh native ordering tests. A deliberately delayed fake callback establishes missing ownership guards, but is insufficient to assert a demonstrated native-browser overwrite.
- Current main has already repaired the automatic-CI documentation contradiction and added staged bootstrap/playback to the manual publisher. That is a resolved historical finding. The playback smoke still forces a legacy/gallery route, and manual visual comparison baselines still have distinct gaps.

No P0 incident, exploitable security vulnerability, universal GPU bottleneck, measured device-memory exhaustion, guaranteed frame-rate improvement, or owner-approved aesthetic improvement is established. These exclusions describe the evidence boundary; they do not replace the actionable defects below.

## 3. Evidence and priority conventions

**R** = reproduced in this review; the text states whether native browser APIs or controlled fault boundaries were used. **C** = confirmed by source/control-flow inspection, without a reproduced end-user failure or measured benefit. **A** = retained artifact inspected, not a fresh hardware run. **O** = supported improvement opportunity whose performance or artistic benefit is unproven. **U** = unresolved hypothesis; do not treat it as an established defect. **Resolved** = the claim was true at the original snapshot but current source/documentation addresses that part. Combinations keep the distinction between a confirmed mechanism and an unmeasured consequence.

**P1**: first repair queue—metadata/output integrity, blocked core availability, or decision-critical validation/measurement prerequisites. **P2**: reliability, responsiveness, correctness, or enabling measurement. **P3**: profile-gated, architectural or artistic investment. No P0 is assigned. Priority is an implementation recommendation, not a severity score inherited mechanically from either model. Measured times under concurrent audit activity are mechanism evidence only.

## 5. Verification dossiers and implementation requirements

The following dossiers consolidate the independent domain reviews. Source support, fresh reproduction and retained artifacts are distinguished within each mechanism. They supplement the C01–C43 register and supply implementation boundaries rather than application patches.

### 5.1 Durable data, outputs and asynchronous ownership

#### Persistence findings and native scheduling

#### R-01 / F02: incomplete traversal is treated as authoritative absence

`walkAudioFiles` suppresses a synchronous `values()` exception and returns an empty traversal at [LibraryScanner.js:55–62](https://github.com/aepler315/midio-pixel/blob/cace36893003e4161b243f22a69204be17181df6/src/library/LibraryScanner.js#L55-L62). `scanDirectory` suppresses any `getFile()` rejection at [165–183](https://github.com/aepler315/midio-pixel/blob/cace36893003e4161b243f22a69204be17181df6/src/library/LibraryScanner.js#L165-L183). `MusicLibrary.rescan` has only generation, cancellation and write-success checks before passing the successfully scanned paths to prune at [MusicLibrary.js:252–267](https://github.com/aepler315/midio-pixel/blob/cace36893003e4161b243f22a69204be17181df6/src/library/MusicLibrary.js#L252-L267). Deletion is actual persistent removal of missing keys at [LibraryDB.js:227–238](https://github.com/aepler315/midio-pixel/blob/cace36893003e4161b243f22a69204be17181df6/src/library/LibraryDB.js#L227-L238).

Fresh adapted Astra probe: seed a.mp3, record playCount 1 and duration 180, make its still-listed handle reject getFile, rescan, restore access, rescan again. The durable row disappears, then returns with playCount 0. Fresh adapted Sol probes independently exercise synchronous directory failure and asynchronous getFile failure: both remove a row with playCount 1/duration 90, return no rescan error, and retain the root. These use the repository's fake IDB and controlled directory/file APIs. An asynchronous iterator rejection propagates; that separate path should not be described as swallowed.

Repair contract: distinguish observed path, successfully read metadata, completeness and failed prefixes. Pruning needs a complete authoritative view or safe per-prefix completeness. Retain previous earned metadata when a known file is inaccessible. A conservative whole-scan failure is a viable smaller repair. Audio files are never deleted by this code.

#### R-02: the old prune can commit after the new scan's write

The service checks generation before and after awaiting prune, but `pruneTracks` performs a readonly lookup and a later readwrite delete without an owner revision: [MusicLibrary.js:255–260](https://github.com/aepler315/midio-pixel/blob/cace36893003e4161b243f22a69204be17181df6/src/library/MusicLibrary.js#L255-L260), [LibraryDB.js:232–238](https://github.com/aepler315/midio-pixel/blob/cace36893003e4161b243f22a69204be17181df6/src/library/LibraryDB.js#L232-L238). A check after the await cannot undo durable deletion.

The **fresh native probe** seeds a.mp3 with playCount 1, opens a genuine readwrite tracks transaction kept active by successive native get requests, starts an old completed scan with an empty keep set, waits until that scan's readonly prune is queued, cancels it, and starts a replacement scan containing a.mp3. When the replacement write has queued, it releases the blocker. The queue is old readonly prune → replacement write → old delete. Production handlers and browser request delivery remain unchanged; a pass-through `transaction` observer only notes creation.

All **five fresh browser contexts** finish with both the visible list and durable list empty. A subsequent healthy rescan restores a.mp3 with playCount 0. The blocker needed only three native requests in each run. This is stronger than the original artificially delayed callback and independently agrees with the earlier consolidation's lead. It proves a valid scheduling path, not ordinary frequency on local drives.

Repair contract: the right to prune must be validated at the durable mutation boundary. A single-tab predicate immediately before the write transaction is a narrow mitigation; a root-scoped revision checked within the transaction is a stronger multi-tab contract. Merely combining the read/delete into one transaction does not define which scan is authorized. Preserve the separate R-01 completeness requirement.
