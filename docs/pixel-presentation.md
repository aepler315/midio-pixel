# Display presentation

> **November 10, 2026:** Cinematic is the only look. The Pixel and Palette
> looks, palettes, dither and the single-stage live path were removed; saved
> records of any look migrate to Cinematic at its Detailed grid (a saved
> Cinematic grid is kept). Passages below about Pixel, Palette, palettes or
> dither describe the removed behavior.

This page describes the current presentation behavior and compatibility rules.
Looks, defaults, rendering architecture and budgets may evolve through
task-authorized experiments under the
[experimental development policy](experimental-development.md); the descriptions
below do not impose permanent preservation requirements.

## Single-stage live Landscape

Pixel and Palette now draw the current Landscape into one selected native-grid
canvas, including the musical sky, water, weather, post effects and
captions. The browser scales the completed picture with nearest-neighbour
sampling. Fullscreen uses the same native backing and CSS cover cropping,
with pointer mapping following that crop. Palette processing and semantic
captures run after the scene is complete.

Native live rendering uses the terrain's own skyline and shoreline. The
separate fine-edge reconstruction and smooth overlays described later in this
page belong to the hybrid path. Cinematic Pixel and explicitly sized offline
captures use that hybrid presentation. Diagnostic URLs select
`?rangePipeline=hybrid`, `native` (resolution-only comparison), or `single`.
Ordinary live Pixel and Palette default to `single`.

The newer sky and musical rules, camera schedules, forest placement and
deformation remain in the native scene. GPU depth snapshots avoid rebuilding
the same opaque terrain depth between soft forest passes. Auto quality counts
sustained missed vsyncs and ends failed detail-recovery probes promptly.
See [renderer restoration measurements](single-stage-rendering.md) for hardware
results, quality levels and remaining measurement limits.

Display settings are available on the title screen and from **Display** during playback. Look and quality are independent:

| Setting | Behavior |
|---|---|
| Pixel | Compose on the selected native grid with unrestricted scene colors, then nearest-neighbour presentation |
| Palette | Same grid, then World, Landscape32, Chroma32 or legacy RGB332 |
| Pixel detail | Classic 320×180 (default), Classic+ 400×225, Medium 480×270, Medium+ 560×315 or Detailed 640×360; Classic+ processes 1.56×, Medium 2.25×, Medium+ 3.06× and Detailed four times as many pixels |
| Dither strength | Off (0), Subtle (0.35), Full (1) |
| Dither style | Ordered Bayer or Selective, which reduces stippling at original-RGB boundaries; RGB332 remains Ordered |
| Auto quality | Existing governor and recovery hysteresis |
| Economy | Pin the cheapest governor rung |
| Fit | Largest aspect-preserving image with opaque black bars |
| Integer | Whole-number physical-pixel scaling; aspect-preserving downscale when smaller than the grid |

Palette and dither controls are enabled for Palette. Style is disabled for RGB332 and Off. Pixel detail and scaling apply to both looks. The grid hint reflects the selected grid. There is no Natural look or Stage resolution control in this fork. Changing display settings while paused draws a new completed frame without advancing song time.

World is a Palette choice; it applies only under the Palette look. World follows the stable world kind: Landscape (the alpine kind) uses Landscape32. Title and unknown world kinds use Chroma32. It never reads the camera, biome, song energy or image histogram. Chroma32 retains distinct cyan, blue, violet and rose accents. Both authored palettes have 32 fixed colors; RGB332 keeps its legacy quantizer.

Preferences live in `midio-pixel:display:v1` (profile schema version 2):

```js
{ version: 2, look: 'pixel', quality: 'auto', palette: 'world',
  dither: 0.35, ditherMode: 'selective', pixelGrid: 'classic', scaling: 'fit', pixelScale: 'original' }
```

Read the new key first, then legacy `smw:display:v2`, then `smw:display:v1`, then the old Stage preset. Never write or delete Midio-5 keys. Every current profile uses `original` (Uniform). Saved Depth selections migrate to Uniform; there is no Depth control or shader branch. Stale Natural settings migrate to Pixel. Migrated v1 choices retain their look, quality, palette, strength and scaling, adding Classic/Ordered; v1 is not deleted. Old `8bit` presets migrate to Pixel/Economy/Classic/Ordered; `8bit-intensive` migrates to Palette/Economy/RGB332/Full/Classic/Ordered. Optional fields are validated independently so a bad grid or style does not discard a valid look. Blocked storage uses usable defaults. Cathode is retired; stale saved world IDs resolve to The Range, including replay and previews. Registered custom worlds still work.

`PixelRenderPolicy` owns both frozen grids and pixel-space dimensions. `PresentingRenderer` supplies that policy to Canvas and Range before drawing and resolves the current world palette before `beginFrame`. Repeating the same effective palette does not invalidate capture or compile another lookup. The current pixel presentation path stays pixelated, including stale raw export overrides. Shared internal rendering utilities remain available to the pixel scene.

Pixel captions use a bundled 5×7 bitmap body at integer native coordinates, doubled at Detailed. Names and required credits wrap into at most six lines per page (54 Classic pixels); longer captions page through the existing hold interval using caption-local song time. Required text is never silently truncated or shrunk. Unsupported characters display a readable `[U+XXXX]` spelling; **Landscape details** retains the original names, regions, statistics, ecoregion and credits. It stays visible while open or focused. Captions are drawn after effects and before quantization, in the captured composition.

Illustrated-world glow uses one instantaneous admitted highlight snapshot and four integer neighboring copies, with total strength capped at 0.10. Alpine glow remains disabled. Heat uses eight-native-pixel cells and integer offsets limited to one Classic pixel or two Detailed pixels, using heard time when available. Title stars retain their seeded layout and transparent backing, with fixed grid clusters and brightness twinkle. The scenic terrain keeps its native grid. The current terrain and near-tree simplification policy uses that grid’s projection-error bounds and protects skyline and shoreline geometry, placements and forest density. Experiments may revise those tradeoffs with corresponding behavior checks and explicit evidence. Pixel materials skip unused preparation and discarded surface texture samples.

Title, playback, live recording and bulk export share the presentation profile. A non-grid pixel output reserves one native-grid working canvas through GraphicsResidency before allocation. Palette processing accepts only a supported native grid and at most 230,400 pixels, never the enlarged output. Selective owns one admitted byte mask (57,600 or 230,400 bytes), computed from the original RGB in the same readback before quantization. Bayer phase is fixed at the grid origin; there is no time term or frame history. Mask admission/commit failure falls back to Ordered for that generation and reports its reason, without retrying every frame. Off, Pixel and RGB332 allocate no edge mask. Scratch surfaces and masks release on grid changes or disposal.

The recorder uses the completed source at its fixed encoded dimensions. For the Landscape sky experiment it redraws the smooth sky at those dimensions and then copies native terrain with smoothing disabled, preserving pixel edges at noninteger export ratios. A live look/grid/scaling change affects the next completed capture without changing video dimensions. Offline export freezes its session profile and quality. A tainted palette canvas falls back to Pixel and reports that status; it retries only after a new presentation generation.

The 30/60 fps cap controls title and playback drawing independently of simulation. Offline export never treats capture cost as governor pressure. The debug overlay reports requested/effective look and grid, requested/resolved/effective palette, dither style/fallback, generation, policy version, scratch bytes and readback/mask/transform/writeback CPU times. Presentation CPU covers the presentation boundary, excluding scene drawing; these CPU measurements are not GPU time or delivered FPS. Copied graphics reports currently include the older subset of these fields; use the overlay or frame evidence for the new settings and fallback details.

Drawing returns an explicit `presented` result. Capture is nullable until a frame finishes successfully; profile/backing resets, allocation failure, context loss, released buffers and disposal invalidate readiness. Export aborts and discards the partial recording on presentation failure. Landscape startup, seeks and rebuilds hold audio and heard time until the complete destination terrain and forest can be drawn. Preparation never publishes placeholder scenery or consumes semantic captures. Active recordings pause across retained-audio preparation, excluding the wait from their duration. Other presentation failures are reported at bounded intervals. A successfully drawn Pixel fallback after palette taint is still a valid frame.

Title and playback keep independent phase-preserving draw deadlines. The playback HUD labels delivered presentation FPS separately from callback FPS; the governor still receives raw callback timing. Integer layout resolves both origin and scale in physical pixels, including the parent's origin and DPR, and applies the logical image dimensions through a transform to avoid CSS layout rounding at fractional DPR.

`npm run test:retro` verifies default Range v2 and explicit legacy, shader/context failures, both-grid checkerboard raster boundaries at four DPRs/eight layouts, meaningful content and temporal changes, exact opaque pre-encode palettes, and export rejection. The bounded pixel browser CI job preserves diagnostic artifacts on failure.

```sh
npm test
npm run lint
npm run test:retro
node tools/palette-bench.mjs
node tools/bulk-export.mjs --help
```

The bulk CLI supports `--look`, `--quality`, `--palette world|range32|chroma32|rgb332`, `--dither off|subtle|full`, `--dither-mode ordered|selective`, `--pixel-grid classic|classicPlus|medium|mediumPlus|detailed` and `--scaling fit|integer`.

The browser smoke needs installed Playwright Chromium or `PLAYWRIGHT_CHROMIUM_PATH`. Software WebGL validates raster output and shaders; it does not establish device FPS, battery use or GPU timings. `palette-bench` reports warm mask/transform arithmetic at both grids, excluding readback, writeback, copying and GPU work. Detailed is an optional detail choice, with higher cost. Implementation evidence, retained variants and unavailable motion/device checks are recorded in the task report (`docs/superpowers/plans/2026-10-14-pixel-mode-progress.md`, removed; see [removed docs](removed-docs.md)); generated captures stay under ignored `.smoke/pixel-mode/`.

## Crest line (Landscape)

The hybrid Landscape compositor, including the Cinematic look, draws steadied terrain crests and lake/river shorelines at output resolution (`src/render/CrestLine.js` math, `src/world/alpine/RangeCrest.js` per frame, `src/world/alpine/CrestProbe.js` GPU probe). Ordinary single-stage Pixel/Palette and `?directTerrain=1` draw no crest overlay.

- **Source.** After each native band renders, a fragment per target column records its first covered row, world elevation and land colour. The refined probe also records up to four water/land edges per column, continuity and nearness. Live readback uses WebGL2 pixel-pack buffers and fences, with three results in flight. Completed copies are collected before the current frame submits terrain work; the near pass only queues its new copy. A sample more than three frames old is omitted while newer pending copies remain in flight, without forcing a synchronous read. View, timeline, seek and size changes reject stale results. Export and contexts without asynchronous support read synchronously. Native rows remain temporal, ownership and visibility metadata; the visible fine outline comes from the separate physical-output silhouette below.
- **Output-resolution edges** (refined probes, levels 0–3). After the near band, `RangeScene._probeFineCrest` renders terrain band ownership and 16-bit distance at the actual output sampling scale, including the scenic camera margin. `PresentingRenderer` sets `range.crestOutputSize` from the physical output canvas; `RangePresentation` converts it against the selected pixel grid. The old fixed four-times-grid limit no longer controls the silhouette. Every fine column's first covered row is packed into extra compact probe rows and retained in `RangeCrest` geometry; the cut, split clip, pockets and strokes follow those points instead of connecting native grid-column centres. Native temporal offsets still steady the line, and a tree crown keeps the native crest where it stands above terrain. A separate 4×4 ownership mask per native cell retains the existing neighbour-colour correction for terrain-over-terrain edges; the water edge block follows it. `edgeRow` locates those blocks after the variable fine rows. Unsupported dimensions or admission failure omit fine geometry rather than inventing a lower-resolution outline.
- **Steadying.** Integer rows are rebuilt to sub-cell positions across columns, then filtered per column (One-Euro, 1.2 Hz minimum cutoff, 0.35 grid-px deadband; motion above 1.5 px/frame passes through; a reversal restarts the speed estimate, so row flicker is absorbed). A smaller kick also passes within the frame: a raw move above 0.7 px in a column that held still for 0.1 s, made the same way by at least 30% of the band's columns (a heave, not a local row flip), and the move right after it (its return). Flicker that starts after a steady spell may therefore show its first flip; sustained flicker is absorbed. Kicks, including one-frame 0.8–1.4 px kicks at 30 and 60 fps, keep ≥90% amplitude with at most one frame of lag (`test/crestLine.test.js`). State resets on a seek, a frame gap (travel, arrival) or a view change, and the line restarts at the raw crest; a cut restarts the slow terms. A quality-mode switch keeps the state.
- **Split cells.** Before palette quantization the grid cells around each smoothed line change owner. Native ownership cells are classified against the filtered native polyline over their whole width, not just at the centre. Their restored lower halves are clipped against the retained fine geometry at output resolution; the dense terrain cut and pocket fill still run when the native split canvas is fully ready, because a fine peak can enter a cell the native classification never crossed. Every cell of the band's land above the line is cut, from its raw crest down (up to 16 rows: a one-cell spire the filter smoothed below), and every crossed cell is split, one or more per column. A crossed cell keeps its upper colour in the grid (transparent over the separate sky) and its lower colour in a grid-sized split canvas drawn at output resolution only below the line. Each half takes the nearest cell fully on its own side (equidistant same-side cells averaged); lower candidates must be opaque land rows of that band, so sky is never sampled into land. Without such a neighbour the upper half takes what lies above the column's raw crest and a land cell's lower half keeps its own colour, so no land is left above the line (`test/crestLine.test.js`: a one-cell spire, a peak, a sharp V). The edit fades with the line (blended toward the raw grid, split halves drawn at the same opacity), so quality switches and new views never pop the silhouette. In Palette mode this rides on the palette readback, and the lower halves go through the grid's own quantizer at their cell after quantization (`quantizeTexel`: same palette, metric and dither), so they match the terrain beside them. Pixel and Cinematic (no palette, so no frame readback to share) read back only each band's rows (±3 cells around its lines, merged where they meet) and shed split cells from governor level 2; the terrain cut below takes over there.
- **Lag alignment.** A live probe is read asynchronously, so it is at least one frame older than the grid it edits; under heave, kicks or camera motion the terrain has moved since. Whenever the frame reads the grid rows anyway (split cells, or the palette frame), each skyline column's grid crest (the first opaque row under a transparent one, within 2 rows of the probe's) is found; when most columns agree on one whole-row offset, every band's raw crest moves by it and skyline columns take their grid crest exactly, so split cells are classified against the terrain the grid shows. The drawn line and the nearer-band clip move instead by the mean offset of the columns within a row of the majority (sub-row, clamped to ±2 rows): per-column offsets are whole rows, but across a skyline their mean follows the true motion, so steady motion of 0.4–0.6 rows per frame (tours, heave, a kick's ring-down) moves the stroke steadily rather than flipping it a whole row between frames (`test/crestLine.test.js`). `crest.lagShift`/`lagLineShift`/`aligned` report it. A synchronous (export) probe is never shifted.
- **Terrain cut.** Over the smooth sky the presenter draws the native frame (nearest, or the Cinematic reconstruction) through `RangeCrest.drawTerrain`: clipped (even-odd) below each skyline column's line, from its raw crest (one row higher while a live probe is unaligned) down to the line's own polyline. Land cells above the line and the upper part of every crossed cell therefore show the sky at output resolution, like split cells, with no readback; sky pockets just below the line (a notch the line smoothed over) are filled with the chunk's land colour as deep as split cells reach. Columns with a nearer band within reach, or with a farther band above (not sky), are left alone. With retained fine geometry the cut always runs, including over a full-strength native split canvas, to keep peaks between native column centres. Only the legacy coarse path skips it when fully aligned split cells already cover the edge. Translucent sky-side content drawn into the grid (a glow or haze layer: alpha below 250) would be removed with the land, leaving the cut's stepped top as a staircase of bare sky against the tinted sky above it; each cut column is therefore refilled only with the cached alpha-verified translucent colour from above its cut top (`crest.glowRefill`). Throttled grid reads never authorize copying current source pixels, which may have become opaque terrain since the sample. View, grid and seek resets discard that cached ownership. Split cells likewise keep it: a cut or crossed cell's upper half takes the alpha-weighted mean of its translucent sky-side neighbours instead of alpha 0. While the line fades in, the cut rows are drawn again at `1 − fade`. `presentationDiagnostics.crestCut` and `crest.cutColumns`/`pockets`/`cutMs` report it; a recording redraws it from the same snapshot.
- **Style.** Fine strokes use the arithmetic RGB mean of the actual composed pixels one physical pixel above and below each painted pixel (`CrestPixelColors.js`). After ownership, split-cell and pocket corrections, two GPU canvas copies freeze that mean into one shared pattern before the first stroke: the upper pixel opaque, then the lower pixel at half opacity. The corrected compositor is opaque, so the mean stays opaque. Scratch covers only the clipped edge bounds, includes stroke padding, and is admitted before allocation. It performs no output CPU readback; unavailable geometry, copy/context failure or denied storage omits the current outline rather than reusing an old pattern. The line therefore follows the visible sky gradient, fog, grading and terrain locally, without an eight-grid-column colour average or a uniform sky fallback. The shared pattern follows physical output coordinates, including capture offsets and scaling. Each band uses one continuous one-physical-pixel stroke, with separate subpaths at missing or skipped samples and clipping against nearer fine geometry. At settled view fade its mean colour is opaque; the existing view fade still controls arrival. Fine strokes use this fixed width and opacity across elevation, rank and visibility metadata. Legacy synthetic and Economy coarse lines keep their earlier style schedule.
- **Shorelines.** Drawn after the water layer: pale (the water's reflected colour lifted toward white, less at night), 70% on the water side, width/opacity by nearness (near strongest, far fading into haze). A near waterline meets the beach at a grazing angle, so its raster edge jumps several rows between columns; shape rules therefore scale with nearness (`SHORE_SHAPE`, far → near). Edges bounding a sliver under 3 rows (a wave crest over a sandbar, a trough) or on the frame edge are not shores; edges of nearby columns link over 2 → 5 rows per column, bridging up to 6 empty columns; chains shorter than 5 → 16 columns are dropped; the rest are rebuilt to sub-cell positions, single-column spikes are replaced, and each chain is smoothed by a robust Gaussian-weighted local linear fit (no pull at the ends, so a sloped shore keeps its end points) whose width scales with the chain's jitter: σ up to 1 → 5 columns at ≥ 0.5 rows of jitter (robust second differences, raster quantization not counted), with a curvature limit of 0.25 rows at full jitter that relaxes as it falls. A clean slope, bend, cove or point is therefore kept as rasterized (within a row), while a jittery near waterline becomes one smooth curve; a chain still more than 1.75 rows RMS from its raw edges is dropped as incoherent. Camera motion and heave move the held shore exactly (the nearest crest band's median shift that frame); the residue goes through a slow filter (0.1 Hz, 0.5 px deadband, no fast path), so 1–2 px music water waves at 0.5–3 Hz move it by under 0.6 px; the drawn chain is smoothed again (out of place, σ/2 of the jitter-scaled width, at least 0.75 columns) because per-point deadbands hold neighbours up to half a row apart. A cut resets it. Only when the smooth water layer exists.
- **Palette.** Fine crest blends use the actual output RGB mean and are not snapped to a palette or rotated away from protected hues: either operation would change the requested neighbouring-pixel blend. Terrain still uses its selected palette. Shoreline colours retain their existing palette snapping and protected-hue treatment. Legacy synthetic probes and the explicit Economy palette scan retain the older coarse-line colour path.
- **Capture.** `crest`/`shore` and the terrain cut remain `compositePixelFrame` layers retained by `PresentingRenderer` for `drawCaptureFrame`. Geometry and temporal state are frozen per frame; a recording recomposes the terrain and copies its own actual output pixels into the mean pattern before drawing the same edge, without advancing the filter.
- **Isolated frames.** Export draws (`exportMode`: visual evaluation, landscape review, the 4K reel re-render) pass `instant`: a frame with no history (the first, a seek, a gap, a new view) draws the line and split cells at full strength, from the raw crest, instead of starting the fade at 0 (it used to reach 3–27%). A frame drawn right after the last one (a travel or arrival frame counts) is continuous: there an export keeps the live fades, including the 0.15 s fade-in on a hard cut or a travel handoff to a new view, so a bulk export still matches playback.
- **Quality.** Levels 0–1 retain refined probes and split cells; Pixel and Cinematic read only the relevant native rows for split preparation. At levels 2–3 they shed split cells while fine geometry and the terrain cut remain; Palette shares its existing frame readback. At level 4+ live Pixel and Cinematic skip probe passes/readback entirely and release the probe buffers: these rungs have no fine outline, cut, split overlay or refined shoreline to draw. Palette and export sampling retain their existing paths. The modern light probe has no fine geometry, so it omits the fine overlay instead of drawing native-column diagonals as a substitute. Refined allocation failure takes the same explicit no-fine-overlay path. Economy skips probe passes; its explicit Palette frame scan remains the older integer-row fallback, while Pixel and Cinematic draw no line. View/seek/gap resets and the existing split/view fades remain. `snapshot().crest` reports the selected mode, readbacks, fade and timing diagnostics. With Building detail enabled, live native growth also respects the current governor cap: Detailed at levels 0–1, Medium+ at 2, Medium at 3, Classic+ at 4 and Classic at 5–6, selecting the finest existing growth rung that fits. This reversible quality cap is separate from memory admission; exports retain the requested growth progression.
- **Cost.** Refined silhouette work scales with the physical output target, rather than a fixed 4× native target. Admission accounts for colour/depth, compact probe/readback rows, fine geometry and bounded colour scratch before allocating `range:crest-fine`; size and mode changes release obsolete targets. Native ownership corrections remain 4×4 masks. The mean-colour canvas is separately admitted as `range-crest-colors` at four bytes per allocated pixel; its clipped bounding rectangle grows in 64-pixel allocation units, reuses storage between frames, and releases on output resize, missing fine geometry or teardown. It uses two GPU copies and no `getImageData` on the output. Fine edge painting takes at most one patterned stroke per band; changing native-column rank or visibility does not create additional clipped GPU draws. The first CPU sampler forced roughly 51 ms of synchronous readback in a measured 1920×1080 Cinematic frame despite reading only nine strips; that implementation was removed. Split storage remains native grid size ×8 bytes (canvas plus CPU image), reserved as `range:crest-split`. Earlier fixed-4× probe and software-raster timings describe the prior implementation; current device performance requires separate measured evidence. Cinematic native working canvases without a palette request `willReadFrequently:false` on their first context creation, for both cold allocation and growing-grid replacement. This avoids Chromium's readback-driven CPU fallback and repeated upgrade/readback cycles; it does not guarantee GPU allocation on every device. A Look/palette change that changes this policy replaces the working canvas even at the same grid size, since later context options cannot change its creation attributes. Palette and other working canvases keep their existing policy.

## Smooth Landscape sky experiment

Alpine Landscape paints moon, sun, stars, aurora, clouds and musical weather into a separate smooth sky layer using the same resolved camera, crop and scenic transform as the terrain. Terrain and its native material responses remain pixelated. Pixel/Palette and Classic/Detailed still control the foreground; the sky stays full-colour and is not palette-quantized.

Windowed live output follows the contained stage CSS size times DPR, capped at 1920×1080, and then the quality ladder's resolution scale (`PerfGovernor.resolutionScale`: 1 at rungs 0–1, 0.85 at rung 2, 0.75 at rung 3, 0.625 from rung 4). A reduced height is rounded down to whole terrain cells and kept at two or more output rows per grid row, or at the display's own height when that is smaller (`RenderOutputSize.stageOutputSize`). A 1080-line Classic stage therefore draws 1080, 900, 720 and 540 lines at rungs 1, 2, 3 and 4–6; Detailed holds 720 from rung 2. A rung change refits the stage; the terrain grid never changes with it. Classic, Classic+, Medium, Medium+ and Detailed keep their 320×180, 400×225, 480×270, 560×315 and 640×360 terrain buffers. Offline exports use their requested dimensions. The sky does not use nearest-neighbour CSS stretching. Above the windowed cap the completed picture is scaled to the display.

Landscape fullscreen instead uses the actual viewport dimensions times DPR, including at reduced quality rungs. It fills the display with uniform cover scaling, cropping the authored scene at the edges where the screen aspect differs. Entering or leaving fullscreen refits and redraws paused playback, and leaving restores the saved scaling preference. This deliberately spends more output pixels than adaptive windowed mode. Android snapshots save only the current detail level at the live backing size; desktop snapshots retain the five full-HD detail captures.

Sky density and lunar textures have bounded, accounted canvas ownership and release on song teardown. The experiment adds no terrain readback or full-frame sky cache. Existing water backdrop storage captures the same sky before far terrain, preserving reflections. Sampleable scenic depth remains required for real depth consumers such as water and shafts, despite removal of the Depth pixel effect.

Use [`npm run review:landscape`](landscape-review.md) for headless review with consecutive PNGs, matching audio, source hashes and controls. It saves reports without opening them. Live cadence traces are separate from fixed-clock visual clips; neither substitutes for physical-display or artistic acceptance.
