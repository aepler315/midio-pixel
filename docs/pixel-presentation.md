# Display presentation

Display settings are available on the title screen and from **Display** during playback. Look and quality are independent:

| Setting | Behavior |
|---|---|
| Pixel | Compose on the selected native grid with unrestricted scene colors, then nearest-neighbour presentation |
| Palette | Same grid, then World, Landscape32, Chroma32 or legacy RGB332 |
| Pixel detail | Classic 320×180 (default), Classic+ 400×225, Medium 480×270, Medium+ 560×315 or Detailed 640×360; Classic+ processes 1.56×, Medium 2.25×, Medium+ 3.06× and Detailed four times as many pixels |
| Dither strength | Off (0), Subtle (0.35), Full (1) |
| Dither style | Ordered Bayer or Selective, which reduces stippling at original-RGB boundaries; RGB332 remains Ordered |
| Auto quality | Existing governor and recovery hysteresis |
| Economy | Pin the cheapest governor rung |
| Fit | Largest aspect-preserving image with opaque black bars |
| Integer | Whole-number physical-pixel scaling; aspect-preserving downscale when smaller than the grid |

Palette and dither controls are enabled for Palette. Style is disabled for RGB332 and Off. Pixel detail and scaling apply to both looks. The grid hint reflects the selected grid. There is no Natural look or Stage resolution control in this fork. Changing display settings while paused draws a new completed frame without advancing song time.

World is a Palette choice; it applies only under the Palette look. The two shipped worlds share the alpine kind, so World follows the experience as well as the stable world kind: Landscape uses Landscape32, and Trio uses Chroma32 so its violet, rose and cyan cast survives quantization. Title and unknown/custom world kinds use Chroma32. It never reads the camera, biome, song energy or image histogram; an experience switch that changes the resolved palette starts a new presentation generation, and the capture record carries the experience. Chroma32 retains distinct cyan, blue, violet and rose accents. Both authored palettes have 32 fixed colors; RGB332 keeps its legacy quantizer.

Preferences live in `midio-pixel:display:v1` (profile schema version 2):

```js
{ version: 2, look: 'pixel', quality: 'auto', palette: 'world',
  dither: 0.35, ditherMode: 'selective', pixelGrid: 'classic', scaling: 'fit', pixelScale: 'original' }
```

Read the new key first, then legacy `smw:display:v2`, then `smw:display:v1`, then the old Stage preset. Never write or delete Midio-5 keys. Every current profile uses `original` (Uniform). Saved Depth selections migrate to Uniform; there is no Depth control or shader branch. Stale Natural settings migrate to Pixel. Migrated v1 choices retain their look, quality, palette, strength and scaling, adding Classic/Ordered; v1 is not deleted. Old `8bit` presets migrate to Pixel/Economy/Classic/Ordered; `8bit-intensive` migrates to Palette/Economy/RGB332/Full/Classic/Ordered. Optional fields are validated independently so a bad grid or style does not discard a valid look. Blocked storage uses usable defaults. Cathode is retired; stale saved world IDs resolve to The Range, including replay and previews. Registered custom worlds still work.

`PixelRenderPolicy` owns both frozen grids and pixel-space dimensions. `PresentingRenderer` supplies that policy to Canvas and Range before drawing and resolves the current world palette before `beginFrame`. Repeating the same effective palette does not invalidate capture or compile another lookup. Product presentation is always pixelated, including stale raw export overrides. Shared internal rendering utilities remain available to the pixel scene.

Pixel captions use a bundled 5×7 bitmap body at integer native coordinates, doubled at Detailed. Names and required credits wrap into at most six lines per page (54 Classic pixels); longer captions page through the existing hold interval using caption-local song time. Required text is never silently truncated or shrunk. Unsupported characters display a readable `[U+XXXX]` spelling; **Landscape details** retains the original names, regions, statistics, ecoregion and credits. It stays visible while open or focused. Captions are drawn after effects and before quantization, in the captured composition.

Illustrated-world glow uses one instantaneous admitted highlight snapshot and four integer neighboring copies, with total strength capped at 0.10. Alpine glow remains disabled. Heat uses eight-native-pixel cells and integer offsets limited to one Classic pixel or two Detailed pixels, using heard time when available. Title stars retain their seeded layout and transparent backing, with fixed grid clusters and brightness twinkle. The scenic terrain keeps its native grid. Additional terrain and near-tree simplification must satisfy that grid’s projection-error bounds while protecting skyline and shoreline geometry, placements and forest density. Pixel materials skip unused preparation and discarded surface texture samples.

Title, playback, live recording and bulk export share the presentation profile. A non-grid pixel output reserves one native-grid working canvas through GraphicsResidency before allocation. Palette processing accepts only a supported native grid and at most 230,400 pixels, never the enlarged output. Selective owns one admitted byte mask (57,600 or 230,400 bytes), computed from the original RGB in the same readback before quantization. Bayer phase is fixed at the grid origin; there is no time term or frame history. Mask admission/commit failure falls back to Ordered for that generation and reports its reason, without retrying every frame. Off, Pixel and RGB332 allocate no edge mask. Scratch surfaces and masks release on grid changes or disposal.

The recorder uses the completed source at its fixed encoded dimensions. For the Landscape sky experiment it redraws the smooth sky at those dimensions and then copies native terrain with smoothing disabled, preserving pixel edges at noninteger export ratios. A live look/grid/scaling change affects the next completed capture without changing video dimensions. Offline export freezes its session profile and quality. A tainted palette canvas falls back to Pixel and reports that status; it retries only after a new presentation generation.

The 30/60 fps cap controls title and playback drawing independently of simulation. Offline export never treats capture cost as governor pressure. The debug overlay reports requested/effective look and grid, requested/resolved/effective palette, dither style/fallback, generation, policy version, scratch bytes and readback/mask/transform/writeback CPU times. Presentation CPU covers the presentation boundary, excluding scene drawing; these CPU measurements are not GPU time or delivered FPS. Copied graphics reports currently include the older subset of these fields; use the overlay or frame evidence for the new settings and fallback details.

Drawing returns an explicit `presented` result. Capture is nullable until a frame finishes successfully; profile/backing resets, allocation failure, context loss, released buffers and disposal invalidate readiness. Export aborts and discards the partial recording on presentation failure. Landscape startup, seeks and rebuilds hold audio and heard time until the complete destination terrain and forest can be drawn. Preparation never publishes placeholder scenery or consumes semantic captures. Active recordings pause across retained-audio preparation, excluding the wait from their duration. Other presentation failures are reported at bounded intervals. A successfully drawn Pixel fallback after palette taint is still a valid frame.

Title and playback keep independent phase-preserving draw deadlines. The playback HUD labels delivered presentation FPS separately from callback FPS; the governor still receives raw callback timing. Integer layout resolves both origin and scale in physical pixels, including the parent's origin and DPR, and applies the logical image dimensions through a transform to avoid CSS layout rounding at fractional DPR.

`npm run test:retro` verifies default Range v2 and explicit legacy, shader/context failures, both-grid checkerboard raster boundaries at four DPRs/eight layouts, meaningful content and temporal changes, exact opaque pre-encode palettes, and export rejection. The bounded pixel browser CI job preserves diagnostic artifacts on failure.

```sh
npm test
npm run lint
npm run test:retro
node tools/palette-bench.mjs
node tools/bulk-export.mjs --help
```

The bulk CLI supports `--look`, `--quality`, `--palette world|range32|chroma32|rgb332`, `--dither off|subtle|full`, `--dither-mode ordered|selective`, `--pixel-grid classic|classicPlus|medium|mediumPlus|detailed` and `--scaling fit|integer`.

The browser smoke needs installed Playwright Chromium or `PLAYWRIGHT_CHROMIUM_PATH`. Software WebGL validates raster output and shaders; it does not establish device FPS, battery use or GPU timings. `palette-bench` reports warm mask/transform arithmetic at both grids, excluding readback, writeback, copying and GPU work. Detailed is an optional detail choice, with higher cost. Implementation evidence, retained variants and unavailable motion/device checks are recorded in the task report (`docs/superpowers/plans/2026-10-14-pixel-mode-progress.md`, removed; see [removed docs](removed-docs.md)); generated captures stay under ignored `.smoke/pixel-mode/`.

## Crest line (Landscape)

Range v2 terrain crests and lake/river shorelines get a steadied, anti-aliased line at output resolution (`src/render/CrestLine.js` math, `src/world/alpine/RangeCrest.js` per frame, `src/world/alpine/CrestProbe.js` GPU probe). Trio and `?directTerrain=1` draw no crest line; the direct path is left unchanged.

- **Source.** After each band (far, mid, near) renders, a fragment per target column finds the band's first covered row, its world elevation (depth unprojected, mapped by `uHeightRange`) and the land colour below it. After the native water pass the probe records up to four water/land edges per column, whether each is a shore (continuous depth) and how near it is. One `width × 14` readback per frame; no grid readback for the line. Live frames read it asynchronously (WebGL2 pixel pack buffer + fence, polled without waiting, three in flight) and use the newest finished result, normally one or two frames old (at most three frames, at any frame rate; a result from another view, song or target size is discarded with everything in flight and that frame reads synchronously). Seeks are found from the clocks: song time running backwards, or ahead of the wall clock by more than 1.5× + 50 ms, discards everything older; a new song (a replay too) does the same via `RangeScene.resetCrestProbe`. The frame freezes what it used, so display and capture match. Export draws (`exportMode`: bulk export, the 4K reel re-render, visual evaluation) and contexts without WebGL2 fences read their own frame synchronously, so exports are reproducible. `snapshot().crest.probeRead`/`probeLag` report which.
- **Steadying.** Integer rows are rebuilt to sub-cell positions across columns, then filtered per column (One-Euro, 1.2 Hz minimum cutoff, 0.35 grid-px deadband; motion above 1.5 px/frame passes through; a reversal restarts the speed estimate, so row flicker is absorbed). A smaller kick also passes within the frame: a raw move above 0.7 px in a column that held still for 0.1 s, made the same way by at least 30% of the band's columns (a heave, not a local row flip), and the move right after it (its return). Flicker that starts after a steady spell may therefore show its first flip; sustained flicker is absorbed. Kicks, including one-frame 0.8–1.4 px kicks at 30 and 60 fps, keep ≥90% amplitude with at most one frame of lag (`test/crestLine.test.js`). State resets on a seek, a frame gap (travel, arrival) or a view change, and the line restarts at the raw crest; a cut restarts the slow terms. A quality-mode switch keeps the state.
- **Split cells.** Before palette quantization the grid cells around each smoothed line change owner. Cells are classified against the drawn polyline (through column centres, so edge → centre → edge across a cell) over their whole width, not at the centre: a peak cell on the line still has corners above it. Every cell of the band's land above the line is cut, from its raw crest down (up to 16 rows: a one-cell spire the filter smoothed below), and every crossed cell is split, one or more per column. A crossed cell keeps its upper colour in the grid (transparent over the separate sky) and its lower colour in a grid-sized split canvas drawn at output resolution only below the line. Each half takes the nearest cell fully on its own side (equidistant same-side cells averaged); lower candidates must be opaque land rows of that band, so sky is never sampled into land. Without such a neighbour the upper half takes what lies above the column's raw crest and a land cell's lower half keeps its own colour, so no land is left above the line (`test/crestLine.test.js`: a one-cell spire, a peak, a sharp V). The edit fades with the line (blended toward the raw grid, split halves drawn at the same opacity), so quality switches and new views never pop the silhouette. In Palette mode this rides on the palette readback, and the lower halves go through the grid's own quantizer at their cell after quantization (`quantizeTexel`: same palette, metric and dither), so they match the terrain beside them. Pixel and Cinematic (no palette, so no frame readback to share) read back only each band's rows (±3 cells around its lines, merged where they meet) and shed split cells from governor level 2; the terrain cut below takes over there.
- **Lag alignment.** A live probe is read asynchronously, so it is at least one frame older than the grid it edits; under heave, kicks or camera motion the terrain has moved since. Whenever the frame reads the grid rows anyway (split cells, or the palette frame), each skyline column's grid crest (the first opaque row under a transparent one, within 2 rows of the probe's) is found; when most columns agree on one whole-row offset, every band's raw crest moves by it and skyline columns take their grid crest exactly, so split cells are classified against the terrain the grid shows. The drawn line and the nearer-band clip move instead by the mean offset of the columns within a row of the majority (sub-row, clamped to ±2 rows): per-column offsets are whole rows, but across a skyline their mean follows the true motion, so steady motion of 0.4–0.6 rows per frame (tours, heave, a kick's ring-down) moves the stroke steadily rather than flipping it a whole row between frames (`test/crestLine.test.js`). `crest.lagShift`/`lagLineShift`/`aligned` report it. A synchronous (export) probe is never shifted.
- **Terrain cut.** Over the smooth sky the presenter draws the native frame (nearest, or the Cinematic reconstruction) through `RangeCrest.drawTerrain`: clipped (even-odd) below each skyline column's line, from its raw crest (one row higher while a live probe is unaligned) down to the line's own polyline. Land cells above the line and the upper part of every crossed cell therefore show the sky at output resolution, like split cells, with no readback; sky pockets just below the line (a notch the line smoothed over) are filled with the chunk's land colour as deep as split cells reach. Columns with a nearer band within reach, or with a farther band above (not sky), are left alone. It runs only where split cells do not already cover the edge: shed (Pixel and Cinematic from level 2), fading, denied a split canvas, rotated, or a live probe that could not be aligned; frames with full split cells on aligned terrain skip it. Translucent sky-side content drawn into the grid (a glow or haze layer: alpha below 250) would be removed with the land, leaving the cut's stepped top as a staircase of bare sky against the tinted sky above it; each cut column's cell just above its cut top is therefore stretched down over the cut (one `drawImage` per run of equal cut tops, from the native grid), where this frame's grid reading shows it translucent, or, on frames without a reading, wherever the last reading saw such content above the skyline (`crest.glowRefill`). Split cells likewise keep it: a cut or crossed cell's upper half takes the alpha-weighted mean of its translucent sky-side neighbours instead of alpha 0. While the line fades in, the cut rows are drawn again at `1 − fade`. `presentationDiagnostics.crestCut` and `crest.cutColumns`/`pockets`/`cutMs` report it; a recording redraws it from the same snapshot.
- **Style.** Dark, never black: the land colour the viewer sees 1–2 cells below the line in the grid (after haze, alpenglow and grading; read during split-cell preparation, or without split cells by a sample-only row read every 0.5 s and right after a reset; the probe's raw band colour only before the first reading) at 0.55× lightness with hue kept, far mixed 25% (mid 10%) toward the air colour; 70% of the width on the land side. Widths/opacities at 1080 lines (scaled by output height, min 1 px): far 1.0–1.5/.35–.50, mid 1.5–2.25/.50–.70, near 2.0–3.0/.70–.90, skyline (upper side is sky) 1.5–1.75/.90–.95: every skyline stroke outranks every near one in opacity, at half its original 3.0–3.5 px width. Within a band `e = 0.6·elevation + 0.4·height above the band's foot`, both followed slowly; nothing reads music energy. Each band's line is clipped above nearer bands' lines. A run of columns is one polyline cut into 8-column chunks (each its own colour, width and opacity) by abutting pixel-column clips; each chunk strokes the path two vertices past its ends with round joins and caps, so chunks meet without a butt-cap wedge at a bend or a doubled overlap. Opacity is further scaled by the edge's visibility in the grid (colour contrast two cells either side, followed over 0.3 s): a band boundary lost in haze is not outlined, the skyline over the separate sky always is. Without a grid reading non-skyline lines use 0.35.
- **Shorelines.** Drawn after the water layer: pale (the water's reflected colour lifted toward white, less at night), 70% on the water side, width/opacity by nearness (near strongest, far fading into haze). A near waterline meets the beach at a grazing angle, so its raster edge jumps several rows between columns; shape rules therefore scale with nearness (`SHORE_SHAPE`, far → near). Edges bounding a sliver under 3 rows (a wave crest over a sandbar, a trough) or on the frame edge are not shores; edges of nearby columns link over 2 → 5 rows per column, bridging up to 6 empty columns; chains shorter than 5 → 16 columns are dropped; the rest are rebuilt to sub-cell positions, single-column spikes are replaced, and each chain is smoothed by a robust Gaussian-weighted local linear fit (no pull at the ends, so a sloped shore keeps its end points) whose width scales with the chain's jitter: σ up to 1 → 5 columns at ≥ 0.5 rows of jitter (robust second differences, raster quantization not counted), with a curvature limit of 0.25 rows at full jitter that relaxes as it falls. A clean slope, bend, cove or point is therefore kept as rasterized (within a row), while a jittery near waterline becomes one smooth curve; a chain still more than 1.75 rows RMS from its raw edges is dropped as incoherent. Camera motion and heave move the held shore exactly (the nearest crest band's median shift that frame); the residue goes through a slow filter (0.1 Hz, 0.5 px deadband, no fast path), so 1–2 px music water waves at 0.5–3 Hz move it by under 0.6 px; the drawn chain is smoothed again (out of place, σ/2 of the jitter-scaled width, at least 0.75 columns) because per-point deadbands hold neighbours up to half a row apart. A cut resets it. Only when the smooth water layer exists.
- **Palette.** Line and shore colours snap to the active palette (RGB332 levels, or the nearest entry in OKLab with hue weighted double) and keep ≥20° from the three protected hues (`ColorLaw.js`); without a palette such colours are rotated out. Only vivid colours count (saturation ≥ 0.4, lightness 0.15–0.92): the palettes' muted terrain browns share the hazard/reward hue range and stay available.
- **Capture.** `crest`/`shore` and the terrain cut are `compositePixelFrame` layers, kept by `PresentingRenderer` for `drawCaptureFrame`; the snapshot is frozen per frame, so recordings redraw it at their size without advancing the filter.
- **Isolated frames.** Export draws (`exportMode`: visual evaluation, landscape review, the 4K reel re-render) pass `instant`: a frame with no history (the first, a seek, a gap, a new view) draws the line and split cells at full strength, from the raw crest, instead of starting the fade at 0 (it used to reach 3–27%). A frame drawn right after the last one (a travel or arrival frame counts) is continuous: there an export keeps the live fades, including the 0.15 s fade-in on a hard cut or a travel handoff to a new view, so a bulk export still matches playback.
- **Quality.** Level 0–1: probe + (Pixel and Cinematic) the band rows read back for split cells. Level 2–3: Pixel and Cinematic shed split cells and their per-frame row read and write-back (the probe, plus a sample-only read of the same rows every 0.5 s for the line colour and edge visibility) and the terrain cut keeps the skyline smooth; Palette keeps them (no extra readback). Level 4+: the probe runs light (`grid` mode: the six crest/colour band passes only, no depth unprojection, no water passes, so no shorelines; elevation holds its last value) and the line holds across the switch with no fade or reset; Palette keeps split cells, Pixel and Cinematic keep the line and the cut. Should no probe arrive there, Palette scans the skyline from its palette frame (integer rows). Split cells fade over 0.5 s when shed or regained; a new view fades in over 0.15 s live (0 for an isolated export frame). Mobile and small windows start at level 1 (`resolvePerfStartLevel`) and may shed further; every rung of auto quality keeps a cut skyline in every look. Economy / 8-bit (`PerfGovernor.economy`, pinned to level 6) keeps the old no-probe path there: no probe passes or readback and no terrain cut; Palette scans its palette frame for an integer-row line, Pixel and Cinematic draw no line. `snapshot().crest.readback` names the readbacks taken (`probe`, `probe+crest-rows`, `probe+crest-sample`, `probe+palette-frame`, `palette-frame`, `none`) with `readRows` and `readbackMs`.
- **Cost.** Probe: 6 tiny passes per frame plus 8 after water, one readback of ≤ 704×14 texels, asynchronous on live WebGL2 frames (GPU time and the remaining synchronous fallback stalls are unmeasured on devices; headless SwiftShader export captures, which read synchronously, spent 20–60 s per frame waiting there). CPU in node with synthetic data (3 bands, 2 shores): update 0.5–0.6/0.9–1.0 ms, grid preparation 0.4–0.5/0.7 ms and stroke path building 0.3/0.5 ms at Classic/Detailed, excluding canvas rasterization and readback; the grid scan (fallback) costs 0.1/0.2 ms. Terrain cut (only on frames without full split cells): path building 0.02/0.04 ms in Chromium; the clipped `drawImage` added 0.3–0.6 ms (Classic) and 1.1–1.2 ms (Detailed) over a plain one at 1920×1080 and 1170×658 in headless Chromium's software 2D raster (a skyline-like clip with steps merged; 0.6–2.0 ms with a step every column), measured against a band-row `getImageData`/`putImageData` of 0.05–0.45 ms there. That software raster has no GPU, so it neither shows the GPU sync a row readback forces on a GPU-backed canvas nor the GPU cost of the clip; both are unmeasured on devices. Lag alignment: within grid preparation noise in node (≤ 0.1 ms). Levels 4+ (auto quality) are the rungs the governor sheds to under sustained load, and they now run the light probe every frame: the six band passes (W fragments each, walking to their first covered row) and the same `W × 14` asynchronous readback; Palette adds split-cell preparation, quantization and the split-canvas upload, Pixel and Cinematic a throttled row sample and the clipped terrain draw. None of that is measured on a device (GPU time of the probe, the clip on a GPU canvas, whether it keeps a phone from recovering a rung); only the software-raster clip figures above exist. The economy floor skips all of it. The Pixel row readback (`getImageData`/`putImageData` on the GPU-backed grid canvas) is unmeasured on devices; the grid canvas is not made `willReadFrequently`, since that would turn every band composite into a CPU upload. Split canvas: grid size ×2 (canvas + CPU image), reserved as `range:crest-split`. `rangePresentation.snapshot().crest` reports mode, fade, resets and CPU timings.

## Smooth Landscape sky experiment

Alpine Landscape paints moon, sun, stars, aurora, clouds and musical weather into a separate smooth sky layer using the same resolved camera, crop and scenic transform as the terrain. Terrain and its native material responses remain pixelated. Pixel/Palette and Classic/Detailed still control the foreground; the sky stays full-colour and is not palette-quantized.

Windowed live output follows the contained stage CSS size times DPR, capped at 1920×1080, and then the quality ladder's resolution scale (`PerfGovernor.resolutionScale`: 1 at rungs 0–1, 0.85 at rung 2, 0.75 at rung 3, 0.625 from rung 4). A reduced height is rounded down to whole terrain cells and kept at two or more output rows per grid row, or at the display's own height when that is smaller (`RenderOutputSize.stageOutputSize`). A 1080-line Classic stage therefore draws 1080, 900, 720 and 540 lines at rungs 1, 2, 3 and 4–6; Detailed holds 720 from rung 2. A rung change refits the stage; the terrain grid never changes with it. Classic, Classic+, Medium, Medium+ and Detailed keep their 320×180, 400×225, 480×270, 560×315 and 640×360 terrain buffers. Trio retains its native grid, and offline exports use their requested dimensions. The sky does not use nearest-neighbour CSS stretching. Above the windowed cap the completed picture is scaled to the display.

Landscape fullscreen instead uses the actual viewport dimensions times DPR, including at reduced quality rungs. It fills the display with uniform cover scaling, cropping the authored scene at the edges where the screen aspect differs. Entering or leaving fullscreen refits and redraws paused playback, and leaving restores the saved scaling preference. This deliberately spends more output pixels than adaptive windowed mode. Android snapshots save only the current detail level at the live backing size; desktop snapshots retain the five full-HD detail captures.

Sky density and lunar textures have bounded, accounted canvas ownership and release on song teardown. The experiment adds no terrain readback or full-frame sky cache. Existing water backdrop storage captures the same sky before far terrain, preserving reflections. Sampleable scenic depth remains required for real depth consumers such as water and shafts, despite removal of the Depth pixel effect.

Use [`npm run review:landscape`](landscape-review.md) for headless review with consecutive PNGs, matching audio, source hashes and controls. It saves reports without opening them. Live cadence traces are separate from fixed-clock visual clips; neither substitutes for physical-display or artistic acceptance.
